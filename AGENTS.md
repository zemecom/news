# AGENTS.md

## 1. Context Reading

- Ключевые файлы контекста (система загружает их автоматически, читай вручную только для глубокого уточнения деталей):
  - `AGENTS.md`
  - `README.md`
  - `docs/PROJECT_MEMORY.md`
  - `docs/PROJECT_STRUCTURE.md`
  - `Makefile`

## 2. Project Memory

- Каноническая память проекта хранится в `docs/PROJECT_MEMORY.md`.
- После каждого значимого изменения (архитектура, контракты, инфра, процессы, backlog) обновлять `docs/PROJECT_MEMORY.md`.
- Правила, относящиеся именно к поведению агента, хранить в `AGENTS.md`.
- Для совместимости с Antigravity файл `.agent/rules/agent_rules.md` должен быть симлинком на `AGENTS.md`.
- Не расширять scope задачи "заодно" без отдельного запроса пользователя.

## 3. Documentation

- **Общая структура**: Карта папок и файлов хранится в `docs/PROJECT_STRUCTURE.md`. Обязательна к ознакомлению для понимания физического расположения модулей.
- **Интерфейсы**: Карта интерфейсов проекта хранится в `docs/PROJECT_INTERFACE.md`.
- Файлы `docs/PROJECT_STRUCTURE.md` и `docs/PROJECT_INTERFACE.md` генерируемые, не поддерживаются вручную.
- Читать `docs/PROJECT_INTERFACE.md` нужно только для задач, затрагивающих бизнес-логику/архитектуру/рефакторинг в `app/` и `src/Modules/`.
- Для чисто инфраструктурных задач (CI/CD, Docker, Makefile и т.п.) чтение `docs/PROJECT_INTERFACE.md` не обязательно.
- После изменений в файлах или классах нужно перегенерировать документацию:
  - `make docs-deps`

## 4. Validation

- Рекомендуется запускать проверки кода до коммита при изменениях в логике (`app/`, `src/Modules/`) через `make` на хосте или напрямую внутри контейнера `app`.
- При коммите проверки запускаются автоматически через git pre-commit hook, поэтому ручной запуск перед `git commit` не обязателен.

## 5. Docker Execution

- **ВСЕ команды разработки и проверки напрямую** (artisan, composer, pest, phpstan, pint, npm и т.д.) ДОЛЖНЫ выполняться СТРОГО внутри Docker контейнера `app`:
  `docker compose exec app <команда>`
- **Исключение — `make`**: команды `make` запускаются на хосте из корня проекта и используются как оркестратор контейнерных команд.

## 6. Self-Verification

- После завершения работы над задачей ОБЯЗАТЕЛЬНО провести этап самопроверки (Self-Verification).
- Проверить:
  1. Соответствие запросу: решена ли проблема пользователя полностью, нет ли лишних действий.
  2. Логику и избыточность: нет ли дублирующего кода или проверок.
  3. Зависимости: если добавлен конфиг, требующий расширение или пакет, добавлено ли это в Dockerfile/composer.json.
  4. Чистоту: не осталось ли мусора (`dd`, `var_dump`, временные файлы).
- Использовать workflow `.agent/workflows/verify_work.md` как чек-лист.

## 7. .agent Catalog

- Рабочий каталог агент-правил: `.agent`.
- Проект содержит правила в `.agent/rules/`. Система Antigravity загружает их в контекст автоматически.
- Для совместимости основной файл локальных agent-specific правил проекта: `.agent/rules/agent_rules.md`, но он должен быть симлинком на `AGENTS.md`.
- Из `.agent/workflows` автоматически подтягивать только названия файлов (без чтения содержимого).
- Если пользователь пишет команду вида `/verify_work` (или `/имя_workflow`), нужно:
  1. прочитать файл `.agent/workflows/verify_work.md` (или соответствующий `.agent/workflows/<имя_workflow>.md`);
  2. выполнить инструкции из этого workflow.
- Если запрошенный workflow-файл отсутствует, явно сообщить об этом пользователю.

## 8. Laravel Octane & RoadRunner

- **Архитектура**: Проект работает в режиме долгоживущих процессов (long-lived processes). Синглтоны и статические переменные сохраняются между запросами.
- **ОБЯЗАТЕЛЬНЫЙ ПЕРЕЗАПУСК**: При внесении любых изменений в код, перед тем как проверять их (через curl или браузер) — ВСЕГДА выполняй `php artisan octane:reload` внутри контейнера.
  *Примечание: Для `make test`, `make test-arch`, `make acceptance` и `make agent-check` достаточно запуска `make` на хосте — перезапуск выполняется внутри контейнера.*
- **Единая команда проверки**: Для упрощения работы используй `make agent-check`. Она автоматически перезапустит Octane, исправит стиль (lint), обновит документацию, запустит статанализ и прогонит тесты.

## 9. CI/CD Pipeline

- В проекте настроен `git pre-commit` hook. Не нужно запускать `make ci-check` вручную перед `git commit` в рамках цепочки команд, так как хук сделает это автоматически (не дублируй проверки).

## 10. AI Rules Management

- **Хранение правил**: Канонический источник локальных правил проекта и инструкций для агента — `AGENTS.md`; в `.agent/` хранится совместимость и workflow-файлы для Antigravity.
- **Создание новых правил**: Если для Antigravity нужен отдельный файл правил в `.agent/rules/`, добавляй в него YAML-блок в начале и не дублируй содержимое, уже описанное в `AGENTS.md`, без необходимости:
  ```markdown
  ---
  trigger: always_on
  ---
  ```
