# Local Project Rules (Laravel, Octane, Docker)

## 1. Docker Execution
- **ВСЕ без исключения команды разработки** (artisan, composer, pest, phpstan, pint, npm) ДОЛЖНЫ выполняться СТРОГО внутри Docker контейнера `app`:
  `docker compose exec app <команда>`
- **Исключение — команды `make`**: Команды из `Makefile` (например, `make test`) уже запускают контейнер внутри себя, поэтому их МОЖНО и НУЖНО запускать прямо на хосте (напрямую из корня). Никогда не запускай остальные команды на хосте!

## 2. Laravel Octane & RoadRunner (ОЧЕНЬ ВАЖНО)
- **Архитектура**: Проект работает в режиме долгоживущих процессов (long-lived processes). Синглтоны и статические переменные сохраняются между запросами.
- **ОБЯЗАТЕЛЬНЫЙ ПЕРЕЗАПУСК**: При внесении любых изменений в код, перед тем как проверять их (тесты, curl, браузер) — ВСЕГДА выполняй `php artisan octane:reload` внутри контейнера. Иначе старый код может зависнуть в памяти и выдавать фантомные ошибки!
- **При ошибках**: В рамках твоих "3 попыток" починки тестов/багов из глобальных правил каждая попытка должна сопровождаться `octane:reload`.

## 3. CI/CD Pipeline
- В проекте настроен `git pre-commit` hook. Не нужно запускать `make ci-check` вручную перед `git commit` в рамках цепочки команд, так как хук сделает это автоматически (не дублируй проверки).

## 4. AI Rules Management
- **Создание новых правил**: При создании нового файла с локальными правилами (например, в `.agent/rules/`) ОБЯЗАТЕЛЬНО добавляй в самое начало файла YAML-блок:
  ```markdown
  ---
  trigger: always_on
  ---
  ```
