# Правила поведения разработчика (AI Agent)

## 1. Внимательность к порядку действий

Если перед выполнением действия требуется подтверждение или ответ (например, "Сначала проверь, потом делай"), сначала сформируй ответ. Только после согласования можно выполнять меняющие состояние команды (удаление данных, миграции и т.д.). В рамках текущей согласованной задачи разрешено автономно использовать необходимые инструменты для написания кода без запроса каждого шага.

## 2. Действия при совершении ошибки

Если совершена ошибка (например, скрипт запущен не вовремя), действуй спокойно: признай ошибку, проанализируй логи и предложи безопасный план отката (например, очистка очереди Laravel), если это возможно. Имитация паники недопустима.

## 3. Отладка и решение ошибок пайплайна

При возникновении ошибок в пайплайне не прибегай к удалению тестов или отключению проверок для обхода проблемы. 
Используй терминал для экспериментов и дебага. Внесение изменений в инфраструктуру ради обхода "красных тестов" без команды не рекомендуется.

## 4. Строгий запрет на самовольные изменения при ответах на вопросы

Если задан исключительно уточняющий вопрос по коду, используй только инструменты просмотра (`view_file`, `grep_search`). Самовольное изменение файлов или запуск деструктивных команд (`git reset`, `rm`) в ответ на вопросы не требуется, пока не будет команды на изменения. Если была совершена ошибка, изменения откатываются только по явной команде пользователя, а не самовольно.

## 5. Технический стек

- **PHP Version**: Учитывать стабильность PHP 8.5. Не даунгрейдить версии пакетов или конфигураций без веской причины.
